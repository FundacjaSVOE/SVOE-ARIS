## 1. Общие принципы взаимодействия агентов

1. Все агенты строго подчиняются правилам из `ARIS_SYSTEM_RULES.md`.
2. Передача данных между агентами происходит через стандартизированные JSON-структуры.
3. Каждая операция логируется для аудита и прозрачности.
4. **Каждый запуск системы имеет уникальный `Execution ID`**, который передается и сохраняется на всех этапах обработки.
5. **Каждый агент обязан сохранять:**
   * Входные данные (Inputs)
   * Результат работы (Outputs)
   * Статус выполнения (`SUCCESS` | `FAILED` | `SKIPPED`)
   * Детализацию ошибок и стек возобновления (Errors / Exception Logs)

## 2. Спецификация агентов

### 2.1. Scheduler Agent (Планировщик и Диспетчер)
* **Назначение:** Управление сеткой вещания, хронометражем и запуск рабочих циклов.
* **Входные данные:** Системное время (Cron / Timer) и параметры сетки публикаций (`09:00` — News, `19:00` — Care & Education).
* **Выполняемая логика:**
  1. В установленное время фиксирует наступление слота.
  2. Генерирует уникальный `Execution ID` для текущего запуска.
  3. Определяет требуемый **тип контента** и **режим запуска** (scheduled / manual / emergency).
  4. Инициализирует рабочий цикл пайплайна.
* **Выходные данные (`ExecutionTrigger`):**
  ```json
  {
    "execution_id": "UUIDv4 / String",
    "slot_time": "09:00 | 19:00",
    "execution_mode": "scheduled | manual | emergency",
    "required_content_type": "Animal Protection News | Animal Care & Education",
    "timestamp": "ISO-8601 Timestamp"
  }
